# Аккаунт 1: месяц и аудит интерфейса

## Итог

Основа навигации подходит, полный задуманный продукт ещё не реализован. Проверялся действующий /spatial/, а не новый макет. Дизайн окна №4 и космическая сцена сохранены.

Аккаунт 1 / пароль 1: синтетический участник Александр, рождение 14.05.1992 09:30 Казань, желания, ресурсы и ограничения; 30 дней 07.09–06.10.2026. 15 вопросов, 8 игр, 7 проб (3 завершено, 2 частично, 1 перенос, 1 отказ), 2 пропущенных шага, одна ревизия. Пропуски входят в записи, не в выполненные пробы. Сценарий написан вручную; это не 30 последовательных вызовов подключённого ИИ. Вопросы в примере повторяются; нельзя заявлять реализованную адаптивную программу. Смысловые дополнения сохранены без превращения их в баллы личности.

Предыдущая сохранённая копия аккаунта перед заменой остаётся в его пространстве хранения под astra-before-example-month-v1. Миграция выполняется один раз; следующие открытия не сбрасывают исправления. Другие аккаунты не заполняются.

## Исправлено

- Сегодня после месяца ведёт прямо к итогам.
- В результатах прямые ссылки: журнал по дням, следующий план, натальная карта.
- Журнал содержит 30 записей; можно раскрыть ответ и открыть исправление. На телефоне строки складываются в карточки.
- Текущий главный раздел отмечается и на вложенных экранах журнала/плана/исправления/профиля.
- Месячный обзор отделяет сделанное от игровых предпочтений, показывает изменения ответов и ограничения. Календарь открывает записи.
- Убрано ошибочное добавление старого 90-дневного шаблона к новому плану; отсутствующий персональный план не выдаётся за готовый.
- Экспорт аккаунта-примера помечается synthetic.
- Подключена рассчитанная карта примера: Astronomy Engine 2.1.19, тропический зодиак, равные дома от ASC, основные аспекты с орбисом 6°. Условие показа — 30 календарных дней с первой записи. Для изменённых данных карта примера не подставляется. Произвольные города, неопределённое время, Плацидус, узлы и персональная трактовка не подключены.

## Чего не хватает — по приоритету

| Приоритет | Требование | Фактическое состояние |
|---|---|---|
| P0 | Последовательный ИИ-диалог на основании только прошлого контекста | Статический планировщик карточек; внешнего ИИ нет |
| P0 | Совместное исследование с выбранным акцентом, обе стороны всегда присутствуют | Нет настройки акцента и общего движка гипотез |
| P0 | Утренний прогноз, неизменяемая версия, вечернее независимое описание и подтверждение сравнения | Статическая символическая подсказка, история проверок пустая |
| P0 | Индивидуальная таблица направлений: факт / гипотеза / вывод / следующий шаг | Есть журнал и расчётный обзор; это не индивидуальная таблица выводов |
| P0 | Выбрать / обсудить / отклонить вариант; утвердить план, отмечать действия | Новый экран плана — незавершённый каркас |
| P1 | Свободный рассказ о себе, регулярное уточнение условий | Желания и ограничения есть, отдельного полного рассказа нет |
| P1 | Почему такой вывод? Согласен / не совсем / не согласен, версии вывода | Исходные записи доступны; обратная связь по выводам отсутствует |
| P1 | Сравнение месяцев, история принятых планов | История ответов есть, месячных снимков и нового цикла нет |
| P1 | Динамика сил/интереса по одинаковой шкале | Шкала в новом исследовании не собирается; график нельзя выдумывать |
| P1 | Точный прогнозный сравнительный график с знаменателем и режимом раскрытия | Нет сохранённых прогнозов и оценок |
| P1 | Надёжное хранение и регистрация клиентов | Локальная демонстрационная авторизация, не серверная защита |

## Навигационное решение

Сохранить четыре главных раздела. Внутри результатов: обзор → моя таблица → исходный день; затем варианты → утверждённый план. Астрология остаётся рядом с опытом, но источники не смешиваются. Нельзя требовать полёта для доступа к любой рабочей функции. Не добавлять второй набор конкурирующих главных меню.

На телефоне прозрачный фон за текстом иногда насыщен планетами/туманом; соответствие контраста WCAG не измерено. Решение с дополнительным затемнением не внедрялось, чтобы самостоятельно не изменить утверждённое оформление.

## Проверка и источники

- UI UX Pro Max: прочитан навык, выполнен поиск по доступной авторизации. Поиск диаграммы статусов дал неподходящие line/radar варианты, они не применены; использованы подписанные числа, календарь и таблица.
- Vercel Web Interface Guidelines: проверены названия, текущий раздел, семантические ссылки, фокус, мобильные размеры. https://github.com/vercel-labs/web-interface-guidelines
- Webapp Testing: принципы проверки действий в браузере; управление через разрешённый CUA, а не отдельный Python Playwright.
- Дополнительно найдены https://github.com/humbleteam/accessibility-audit и https://github.com/better-auth/skills — не установлены и не выдаются за проведённую сертификацию/подключённую авторизацию.
- Установлены ui-ux-pro-max, web-design-guidelines, webapp-testing.
- Astronomy Engine: https://github.com/cosinekitty/astronomy (MIT). Геометрия ASC проверена на восточном горизонте; независимая сверка всех координат второй эфемеридой пока не выполнена.
